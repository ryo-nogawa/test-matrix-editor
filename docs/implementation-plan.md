# 実装計画

[要件定義書](requirements.md)・[Markdown書式仕様書](markdown-format.md)・[AIへの指示文](ai-prompt.md) をもとにした実装計画です。

- 版：0.2（2026-10-28）M7「名前を付けて保存」を追加

## 1. 方針

- **配布物は1ファイル**：`dist/test-matrix-editor.html`（HTML・CSS・JavaScriptを1つにまとめたもの）。外部ライブラリ・CDNは使わない
- **開発中はファイルを分ける**：役割ごとに `src/` に分けて書き、小さなビルドスクリプトで1ファイルにまとめる
  - 理由：Markdownの処理やデータ操作を画面から切り離し（要件定義書 7章）、画面なしでテストできるようにするため
- **開発用の道具は Node.js の標準機能だけ**：ビルドは自作スクリプト、テストは `node:test`（標準のテスト機能）。npmパッケージは入れない
- **ロジックを先に、画面を後に**：テストしやすい部分から作り、画面は最後に組み立てる

## 2. 構成

```
test-matrix-editor/
├── docs/                     … ドキュメント
├── src/
│   ├── core/                 … 画面に依存しない処理（Node.jsでテストする）
│   │   ├── marks.js          … 印の定義と表記揺れの正規化
│   │   ├── markdown.js       … Markdownの出力（serialize）と読み込み（parse・検証）
│   │   ├── matrix.js         … データ構造と操作（行・列の挿入・削除・複製、採番）
│   │   ├── checks.js         … 改変チェック・網羅チェック・セル結合の計算
│   │   ├── history.js        … 元に戻す・やり直し
│   │   ├── prompt.js         … AIへの指示文の組み立て（本文は docs/ai-prompt.md からビルド時に埋め込む）
│   │   └── savefile.js       … 【M7】データ入りHTMLへの埋め込み・取り出し、ファイル名、開くときの判定
│   ├── ui/                   … 画面（ブラウザでだけ動く処理）
│   │   ├── table.js          … 表の描画、固定表示、結合
│   │   ├── editing.js        … セルの編集、プルダウン、＋ボタン、右クリックメニュー
│   │   ├── dialogs.js        … ダイアログと、画面下のお知らせ
│   │   ├── toolbar.js        … ツールバー（出力・読み込み・指示文コピー）
│   │   ├── storage.js        … ブラウザ内への一時保存
│   │   └── files.js          … 【M7】保存の画面、上書き保存、ダウンロードへの切り替え
│   ├── app.js                … 起動処理。各モジュールを組み合わせる
│   ├── styles.css
│   └── index.html            … 雛形（ビルド時にCSS・JSを埋め込む）
├── test/
│   ├── fixtures/             … テスト用のMarkdown（試行で得た表、わざと崩した表）
│   └── *.test.js
├── scripts/
│   └── build.js              … src/ を1ファイルにまとめて dist/ に出力
└── dist/
    └── test-matrix-editor.html … 配布物
```

- `src/core/` のファイルは、ブラウザでもNode.jsでも読めるように書く（最後に `module.exports` がある場合だけ書き出す形）
- ビルドは「ファイルを決まった順につなげて `<script>` と `<style>` に埋め込む」だけの単純なものにする

## 3. データ構造（案）

```js
{
  headers: ["種類", "対象", "項目", "パターン"], // 階層の列の見出し（左から親→子）
  valueHeader: "具体値",                         // 具体値の列の見出し
  testCount: 7,                                  // 試験の列の数（項番は常に 001〜 の連番なので番号は持たない）
  rows: [
    {
      id: "r1",                                  // 画面の操作や改変チェックで行を追うためのID
      levels: ["入力", "ログインAPI", "リクエスト", "必須項目あり"],
      value: "login()",
      marks: ["○", "", "○", "○", "○", "○", "○"] // 試験の列の数と同じ長さ
    }
  ]
}
```

- 試験項番は「左から何番目か」で決まるため、データには持たない（常に振り直す、という決定事項をそのまま表現できる）
- 操作はすべて「今の状態を受け取り、新しい状態を返す関数」にする。元に戻す・やり直しは、状態の履歴を持つだけで実現できる

### M7：名前を付けて保存（要件定義書 5.5）

#### 設計

**データ入りHTMLの作り方**

- 起動直後、表を描く前に、自分自身のHTML（`document.documentElement.outerHTML`）を控えておく。保存するときは、その中のデータを埋め込む部分だけを差し替えて、新しいHTMLを作る
  - 理由：ブラウザは `file://` で開いた自分のファイルを読み直せない。表を描く前に控えるので、描いた表やダイアログは含まれない
- データを埋め込む場所として、`src/index.html` の `<head>` に `<script type="application/json" id="matrix-data"></script>` を置く
  - 中身はJSON。`<` を `<` に置き換えて、データの中の文字で `</script>` が途切れないようにする
- 埋め込むデータ：

```json
{
  "format": "test-matrix-editor",
  "version": 1,
  "toolVersion": "0.2.0",
  "fileId": "f-1a2b3c4d",
  "name": "ログインAPI試験",
  "savedAt": "2026-10-28T10:15:30.000Z",
  "matrix": { "headers": [], "valueHeader": "具体値", "testCount": 0, "rows": [] }
}
```

- `toolVersion` は、ビルド時に `package.json` の `version` から埋め込む。M7で `0.2.0` に上げる

**自動保存の枠**

| 開いているもの | 自動保存の枠（localStorage の名前） |
| --- | --- |
| 元のツール（データが埋め込まれていない） | `test-matrix-editor/matrix`（今と同じ） |
| 保存したHTML | `test-matrix-editor/file/<fileId>` |

- 自動保存のデータにも `name` と `savedAt` を含める
- 「名前を付けて保存」をするたびに、新しい `fileId` を作る（別のファイル＝別の自動保存の枠）
- 元のツールから初めて保存したときは、その画面を保存したファイルとして扱い、以後の自動保存はファイルの枠に行う。名前の無い枠は空に戻し、元のツールを次に開くと新規の状態から始まる

**開いたとき**

- 埋め込まれたデータがあれば、その `fileId` の自動保存を調べる
- 自動保存の `savedAt` が埋め込まれたデータより新しく、内容も違えば、「続きから開く」「保存した内容で開く」を選ぶダイアログを出す
- 元に戻す・やり直しの履歴は、空の状態から始める

**保存の操作**

- 「名前を付けて保存」：保存の画面（`showSaveFilePicker`）を出す。ファイル名の初期値は「名前.html」
  - 利用者がキャンセルしたときは何もしない
  - 保存の画面が使えない、または保存に失敗したときは、通常のダウンロードで保存する
- 「保存」：その画面で最後に保存したファイル（`FileSystemFileHandle`）を覚えておき、同じファイルに上書きする。覚えていなければ「名前を付けて保存」と同じ動きにする
- ファイル名に使えない文字（`\ / : * ? " < > |`）は全角に置き換える。名前が空のときは「無題の試験マトリクス」
- 名前の変更は、元に戻す・やり直しの対象にしない（表の内容の操作ではないため）
- 最後にファイルへ保存した後に変更があれば、タブの名前の先頭に「*」を付け、ステータスバーに「未保存の変更あり」と表示する

**古い版で保存したHTMLの読み込み**

- 読み込みのファイル選択で `.html` も選べるようにし、埋め込まれたデータを取り出して読み込む（1回の操作として履歴に積む）
- 名前は取り込む。`fileId` は取り込まない（読み込んだファイルと今の画面は別物として扱う）

## 6. リスクと対策

| リスク | 対策 |
| --- | --- |
| `file://` でブラウザ保存が使えない（会社のポリシーなど） | M0で先に確認する。使えない場合は、ファイル出力によるバックアップを前提にした運用に切り替える |
| 300列で描画が重い | 最初は「変更のたびに表全体を描き直す」単純な方式で作り、M6で計測して必要なら部分更新にする |
| ビルドの仕組みが複雑になる | 「ファイルをつなげて埋め込むだけ」に留める。モジュールの変換などはしない |
| 【M7】起動時に控えたHTMLに、ブラウザの拡張機能などが差し込んだ要素が混ざる | スクリプトの最初（表を描く前）に控える。保存したHTMLを開き直して、ツールとして正しく動くことをテストで確かめる |
| 【M7】保存の画面（`showSaveFilePicker`）が会社の環境で使えない | 使えないときは通常のダウンロードに切り替える。どちらの方法で保存したかを、お知らせで表示する |
| 【M7】保存したHTMLを何度も保存し直すと、ファイルが壊れる・大きくなる | 差し替えるのはデータを埋め込む部分だけにする。「保存 → 開く → 保存」を繰り返しても、ファイルの大きさが増え続けないことをテストで確かめる |
