# 試験マトリクス作成支援ツール 要件定義書（ドラフト）

## 1. 目的・背景

- ソフトウェアテストの試験項目書を作るときに、マトリクスで要点を整理している（対象：業務システムのAPIなど）。
- 今はExcelで作っているが、Excelを使えない環境を前提に、ブラウザで動くツールに置き換える。
- いちばんの課題：網羅できているかを確認しながら、行（条件）と列（試験項番）を追加していく作業の手間が大きい。
- **ツールの役割**：行と列を手軽に追加・編集できる編集画面を提供すること。条件の自動生成はしない。

## 2. 利用者

- 作成者本人と、チームの他のメンバー。

## 3. スコープ

### 対象範囲（やること）

- マトリクスの左側（条件の定義）を作成・編集する
- 行・列・階層の列をプラスボタンで追加する
- Markdown形式で出力する
- AIが印を付けたMarkdownを読み込み、見やすい表として表示する
- 作業途中のデータをブラウザ内に一時保存する

### 対象外（やらないこと）

- 試験の組み合わせや印の自動生成（印付けはツールの外でAIが行う）
- 試験項目書への流し込み、Markdown以外の形式での出力
- サーバー側の処理、複数人での同時編集

## 4. 利用フロー

1. ユーザーがツール上で左側の条件をすべて入力する
2. 「出力」ボタンでMarkdownを出力する
3. Markdownを外部のAIに渡し、試験項番ごとに印を付けてもらう
4. AIが完成した表をMarkdownで返す
5. 返ってきたMarkdownをツールに読み込み、整形された表として表示する

## 5. 機能要件

### 5.1 表の構造

- 左側（ユーザーが入力する列）のデフォルトは「種類」「対象」「項目」「パターン」「具体値」の5列
- 見出し名はユーザーが自由に変更できる
- 階層の列はプラスボタンで追加できる（段数は可変。想定は4段程度だが上限は設けない）
- 「種類」の初期分類は「入力（事前条件）」「機能（処理）」「出力（結果）」
- 右側は試験項番の列（001, 002, …）。プラスボタンで追加できる
- 「具体値」は階層ではなく、条件に付く補足の値として扱う
- 運用ルール：種類が「機能」の行は、処理される順番に上から並べる（AIへの指示文で「表の上から順に処理される」とみなすため）

### 5.2 セルの印

| 印 | 意味 |
| --- | --- |
| ○ | 確認する観点 |
| − | 手前の条件で処理が止まり、到達しない |
| 空欄 | 該当しない |

- 印の種類は最大3種類程度を想定

### 5.3 階層の表示

- Markdownでは、親・子・孫の値を別々の列に分け、行ごとに省略せずに書く
- 画面に表示するときに、同じ値が続くセルをツールが自動で結合して見せる

### 5.4 Markdownの出力・読み込み

- 出力はボタンを押したときだけ行う
- 出力の方法は2つ：クリップボードへのコピー、`.md` ファイルとしての保存
- 読み込みの方法は2つ：貼り付け欄へのテキストの貼り付け、`.md` ファイルの選択
  - AIとのやり取りはコピー＆貼り付け、バックアップと復元はファイルで行う想定
- 見出し行で、階層の列・具体値の列・試験項番の列の境界が分かるようにする
- 読み込み時に書式を検証し、崩れていればエラーとして知らせる
- 出力したMarkdownを読み込み直せば、作業状態を復元できる（バックアップを兼ねる）

### 5.5 保存

- 作業途中のデータはブラウザ内に一時保存する

### 5.6 Markdownの書式ルール

- 詳細は [Markdown書式仕様書](markdown-format.md) に定める
- 見出しは1行のみ。「試験項番」のまとめ見出しは出力に含めず、画面表示時にツールが付ける
- 試験項番の列は、見出しが数字だけの列として判別する（例：001）
- 読み込み時に記号の表記揺れをフォーマッターのようにそろえる（◯・O → ○、各種ダッシュ → −）
- どの記号にも当てはまらない文字は変換せず、警告を出す

### 5.7 AIへの指示文

- 印の定義と書式ルールを含む指示文をツール側で用意し、Markdownと一緒にコピーできるようにする
- 指示文の案は [AIへの指示文](ai-prompt.md) に定める

### 5.8 補助機能

- **改変チェック**：読み込み時に、左側の条件が出力時から書き換えられていないかを照合する
- **網羅チェック**：どの試験にも丸が付いていない条件の行と、丸が1つもない試験の列を強調表示する
- **列の複製**：試験の列をコピーして、一部だけ変更できるようにする

### 5.9 エラーと警告の表示

- **エラー**（表の形が壊れていて読み込めない）：ポップアップで原因を表示し、読み込みを中止する
- **警告**（読み込めたが、不明な記号や改変などがある）：ポップアップで件数を表示し、該当するセルを色で強調する

### 5.10 画面設計

- **ツールバー**（画面上部）：「Markdown出力」「読み込み」「指示文コピー」「元に戻す」「やり直し」
- **表**：既存のExcelとほぼ同じ見た目。セルをクリックするとその場で編集できる
- **行の挿入**：行の間にマウスを乗せるとプラスを表示し、そこに挿入する。新しい行は、挿入位置の上の行から、階層の最下段の1つ手前までの値を引き継ぐ（最下段と具体値は空にする）
  - 例：上の行が「機能 / 会員確認 / 会員情報の検索 / 見つかる / true」なら、新しい行は「機能 / 会員確認 / 会員情報の検索 / （空） / （空）」
  - 先頭に挿入する場合など、上の行が無いときはすべて空にする
- **列の挿入**：試験の列も同じ操作感で、列の間に挿入できる。挿入・複製・削除のたびに試験項番を左から振り直す
- **階層の列の追加**：階層の列の右端のプラスで追加する
- **印の編集**：クリックしたセルにだけプルダウン（○ / − / 空欄）を表示する
- **右クリックメニュー**：行・列を右クリックすると、「挿入」「複製」「削除」のメニューを表示する（複製は試験の列のみ）
- **削除と取り消し**：行・列は右クリックメニューから削除できる。Ctrl+Zで元に戻し、Ctrl+Yでやり直す
  - Markdownの読み込みも1回の操作として扱い、Ctrl+Zで読み込む前の状態に戻せる
- **固定表示**：横にスクロールしても、左側の条件の列と見出しの行は固定する

## 6. 非機能要件

| 項目 | 要件 |
| --- | --- |
| 規模 | 行は最大50程度、試験項番の列は最大300程度 |
| 動作環境 | Microsoft Edge |
| ネットワーク | インターネットに接続できない環境で完全に動作すること |
| 配布形態 | HTML・CSS・JavaScriptを1ファイルにまとめ、ファイルを開くだけで使える |
| 依存関係 | 外部ライブラリやCDNは使わない |

## 7. 設計方針・リスク

- **AIの出力形式のずれ**：AIが返すMarkdownの書式は揺れやすい。表の書式を厳密に定め、読み込み時に検証する。
- **横に長い表**：300列の表ではAIが列の位置を取り違える恐れがある。まずは表全体を一度に渡し、品質が悪ければ縦横の入れ替えや分割を検討する。
- **形式の変更に備える**：Markdownの出力・読み込み処理は画面の処理から切り離し、後から形式を変えられるようにする。
- **一時保存の消失**：キャッシュを消すとデータが消えるため、Markdownの出力をバックアップとして使う。ファイルを直接開いたときの保存の挙動は、Edgeで事前に確認する。

## 8. 未決事項

- ファイルを直接開いたとき（`file://`）のブラウザ保存の挙動（Edgeで要確認。実装の初期に確認用HTMLで試す）
- 網羅チェックの対象に、出力の行を含めるか（指示文0.3では、参考資料がないと出力の行が空欄で返るため。画面を見て決める）
